  ## 2. Lease correctness holes
  - **TTL = AckWait (15 m) is wrong.** Sync budget is 30 m (`consumer.go:44`). InProgress is a fire-and-forget `+WPI` publish; KV `Update` is a request/reply. They fail independently, so "lease expires ⇔ redelivery" doesn't hold. Lease expiring at minute 15 of a 25-m bootstrap lets a fanout job re-bootstrap — the incident. Use TTL ≈ syncTimeout + 2 renewals (~40 m); renew every 5 m; nats.go legacy KV resets age on `Update` (`nats.go/kv.go:58`), so MaxAge works. Per-key TTL would need the `jetstream` API (`jetstream/kv_options.go:126`); unnecessary.
  - **Dead holder + acked blocked jobs = lost work.** Rationale "holder's own message redelivers after AckWait" fails: the redelivery arrives while the dead pod's lease is still held, gets classified *blocked*, and is acked (A) or burns deliveries (B). Nothing ever syncs. **Steal rule**: a blocked job takes over (CAS `Update` with its pod) when `lease.stream_seq == own seq` or `now − started_at > syncTimeout + 2 m`. Clock skew is seconds; slack covers it.
  - **Kinds share the ULID.** A namespace-kind job (`refs/heads/entire/native/*` only, `syncer.go:141-146`) blocked behind a github bootstrap and "dirty"-collapsed into a github follow-up loses the namespace push entirely (github scope excludes it, `:125`). Key the lease `ULID/kind`; ref sets are disjoint, so cross-kind concurrency is safe.

  ## 3. A vs B
  B: escalating naks burn `NumDelivered`, and the final-delivery "ack silently" is lost work; it also pollutes `max_deliveries` semantics the rekicker relies on. Reject.
  A as written: (i) in-process loop shares one 30-m `syncCtx` (`consumer.go:451`), one AckWait extender, and a stale position snapshot (`:398`); (ii) unbounded under continuous pushes — one message owns a pod indefinitely. Lost-wakeup is actually safe *if* ordering is dirty-CAS-succeeds → Ack, and holder deletes with `LastRevision` of the revision it read dirty=false on (retry on `ErrKeyExists`). Holder Term/exhaust while dirty: release still must honor dirty.
  **Fix**: lease value stores the latest blocked `subject+payload`. On release, if dirty → republish it with a fresh `Nats-Msg-Id` (exactly `failindex.RekickMsg`, `failindex.go:47-53`; worker already has `mirror.>` publish). No loop, no shared budget, naturally coalesces N pushes to one job, bounded per message. If republish fails, fall back to one in-process incremental.
  Blocked ack: publishes no completion (holder's `ready` flips status; fine), must not touch the failure index; a blocked rekick leaves its entry, next tick re-kicks — acceptable. Add outcome `deferred`, excluded from the failure-rate numerator like `raced` (`docs/design/mirror-worker-capacity.md:95`).
